## 4. Architecture plan corrections (Coach review — see the delta preserved in the plan file)

1. **Comp/partner writer split.** `activateEntitlementsForPayment()` unconditionally created a placement entitlement (hardcoded `placement_source: "stripe_paid"`) and stamped `metadata.source: "stripe_webhook"` regardless of true provenance. Split into `activatePackageEntitlement()` (entitlement-only, truthful `sourceDescriptor`) + `activatePlacementForRealPayment()` (placement-only, explicit `placementSource`), with `activateEntitlementsForPayment()` kept as a backward-compatible wrapper requiring zero call-site changes.
2. **Explicit package-benefit mapping**, not inferred from placement/tier/account.
3. **Retired $79 products centrally unsellable** — `stripeEligible:false`/`promoEligible:false`, not just a documentation flag — proven via the existing generic `validateRevenueCheckoutRequest` guard, plus two route-level defense-in-depth checks.
4. **Server boundary corrected** — `categoryCommercialPlan.ts` is `"server-only"`; the dashboard client never imports it, only the authenticated dashboard route does.
5. **Idempotency proof** — the durable M4 partial unique index (`listing_package_entitlements_live_uniq`), not a pre-check SELECT.

**Final Addendum (narrower correction, applied after round-1 approval):** the historical print-included compatibility fallback was narrowed to require BOTH `grant_source='print_included'` AND a qualifying non-digital-only `package_tier` (category alone is insufficient); and the resolver was corrected to never use `.maybeSingle()` — a listing may legitimately hold multiple simultaneously-live entitlements (different `package_key`s), and a canonical base-package row must always be preferred over a simultaneously-active legacy addon row, never the reverse.
