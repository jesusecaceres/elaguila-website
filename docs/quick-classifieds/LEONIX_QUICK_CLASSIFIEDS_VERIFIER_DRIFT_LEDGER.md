# LEONIX QUICK CLASSIFIEDS — VERIFIER DRIFT LEDGER (pre-QA forensic gate, 2026-09-20)

Purpose: classify, one by one, every repository verifier that fails on the Quick feature branch, and decide whether the failure is a stale test expectation or a real current-main defect that Quick depends on.

Method used in this mission (not carried over from prior docs):
1. Each script was re-run on branch HEAD `2c70eb10` (`npx tsx` for `.ts`, `node` for `.mjs`); the first failing assertion was captured.
2. Every `app/…`, `scripts/…`, `supabase/…` path literal referenced by each script was extracted and intersected with `git diff --name-only origin/main HEAD` (42 files). For every script the intersection is EMPTY, so the script reads exactly the same source on the branch as on `origin/main` (`fd909499`); three scripts also shell out to `git`, but only for file listing, not for branch-dependent expectations. The branch result is therefore the main result by construction. (The previous integration gate additionally reproduced all 11 on a pristine `origin/main` worktree; that observation is consistent with this analysis but is not relied upon here.)
3. "Quick depends" is answered from the Quick source: what Quick reads at runtime is the category registry (`categoryRouteRegistry.ts`), the canonical draft stores, gates, previews and publishers cited in the Final Proof Matrix — not the copy strings, hub cards or legacy literals these tests assert.

Allowed actions: `NO_ACTION_QUICK_UNAFFECTED` · `SEPARATE_MAIN_CLEANUP_REQUIRED` · `QUICK_REPAIR_REQUIRED`.
